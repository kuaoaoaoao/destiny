# 17 - 场景制作与 TileMap 拼装工作流

> ⭐ 本文档解决一个核心问题：**AI 生成的"整张场景图"无法直接当游戏地图用**。本文档定义正确的扁平手绘 2.5D 场景工作流——**生成"素材包"，在 Godot TileMap 里拼装**。
>
> **本文档取代 16 号文档中"第四、五节场景/CG 生成规范"里关于"整张场景图"的部分。角色、UI、CG 单张图的规范仍以 16 号为准。**

---

## 一、问题：为什么"整张图"不能当地图

### 1.1 你遇到的问题

用 AI 生成一张漂亮的小镇全景图，放进游戏当背景，结果发现：

| 玩家期望 | 实际效果 |
|---------|---------|
| 角色能"走"在场景里 | 角色"飘"在画上面，像贴纸 |
| 有可走路径和障碍物 | 整张图连成一片，无法区分路和墙 |
| 能局部变化（白天/拆建筑） | 改一处要重新生成整张图 |
| 角色和场景风格统一 | 场景细节多，小角色放上去格格不入 |

### 1.2 根本原因

**游戏地图（如星露谷）不是"一张图"，而是用几十上百个"小图块（tile）"在引擎里拼出来的。** 每个地砖、每棵树、每栋房都是独立素材，有"可走/障碍"属性。

AI 生成"一整张场景图"，本质上是生成了一张"画"，不是"地图数据"。**无论扁平还是像素，整张图都不能当地图。**

### 1.3 正确做法

```
❌ 错误：AI 生成一整张地图当背景
✅ 正确：AI 生成"地图元素素材包"，在 Godot 里用 TileMap 拼成地图
```

## 二、TileMap 工作流原理（3 分钟看懂）

### 2.1 什么是 TileMap

**TileMap（瓦片地图）** = 用小图块拼大地图的技术。

想象你在玩拼图：
- **地砖（Tile）**：一块 48×48 像素的小图，比如一块草地
- **TileSet**：一整套地砖的集合（草地、土路、石头、水面……）
- **TileMap**：把这些地砖铺成一张大地图

```
地砖库(TileSet)：          拼成的大地图(TileMap)：
┌──┬──┬──┐               草草路路草草
│草│路│石│               草路路路草草
├──┼──┼──┤      →        路路房房路草
│水│房│树│               草路房房路路
└──┴──┴──┘               草草路路草树
```

### 2.2 地图的两类素材

| 类型 | 说明 | 例子 | 拼法 |
|------|------|------|------|
| **地砖（Tile）** | 可重复铺满地面的基础图块 | 草地、土路、石板、水面 | 在 TileMap 网格里刷 |
| **物件（Object/Prop）** | 独立放在地图上的东西 | 房子、树、小卖部、秋千 | 作为独立精灵摆放 |

### 2.3 为什么这样做才对

| 优势 | 说明 |
|------|------|
| ✅ 角色不飘 | 地砖有网格，角色贴着网格走，像真踩在地上 |
| ✅ 可走/障碍 | 每种地砖可标记"可走"或"障碍"，角色自动绕开墙 |
| ✅ 可修改 | 想加一条路？刷几块地砖就行，不用重画整张图 |
| ✅ 可复用 | 同一套地砖能拼出无数张不同地图 |
| ✅ 性能好 | 地砖重复使用，内存占用低 |
| ✅ 风格统一 | 所有地图用同一套地砖，天然统一 |

## 三、扁平手绘 + TileMap 的素材清单

### 3.1 你需要生成的不是"地图"，而是"素材包"

**MVP 需要的素材包（取代之前的整张场景图）：**

#### A. 地砖集（TileSet）—— 基础地面

| 地砖 | 用途 | 数量变体 |
|------|------|---------|
| 草地 | 院子、田野 | 3-4 种（深浅/有花/有草丛） |
| 土路 | 小镇道路 | 2-3 种（直/弯/路口） |
| 石板路 | 学校、集市 | 2 种 |
| 室内木地板 | 家里 | 1-2 种 |
| 室内地砖 | 学校、小卖部 | 1-2 种 |
| 水面 | 小河 | 2 种（带波纹） |

**每个地砖规格：48×48 像素，可无缝拼接（边缘连续）**

#### B. 地砖边缘过渡（重要！）

不同地砖交界处需要"过渡地砖"，否则会有硬边：

| 过渡 | 说明 |
|------|------|
| 草地→土路边缘 | 草地长到路上的渐变 |
| 草地→水面边缘 | 河岸 |
| 土路→石板边缘 | 路口衔接 |

#### C. 独立物件（Objects）—— 放在地砖上

| 物件 | 用途 | 备注 |
|------|------|------|
| 老槐树 | 核心地标 | 大尺寸（如 192×192） |
| 普通树木 | 装饰 | 中尺寸（96×96） |
| 灌木丛 | 装饰 | 小 |
| 你的家（外观） | 主角家 | 大（240×192） |
| 民房×2-3 种 | 邻居家 | 中大 |
| 小卖部（外观） | 大壮家 | 大 |
| 学校（外观） | 上学 | 大 |
| 老槐树下的秋千 | 情感物件 | 中 |
| 石凳、长椅 | 装饰 | 小 |
| 路灯 | 装饰 | 小 |
| 栅栏 | 围栏 | 可拼接 |

### 3.2 素材包 vs 整张图的工作量对比

| 方式 | 生成 | 后期 | 灵活度 |
|------|------|------|--------|
| 整张图（旧） | AI 1 张 | 无法改 | 极低 |
| **素材包（新）** | AI 20-30 个小图 | 拼装1次 | **极高** |

素材包前期要生成的图多一些，但**一次拼好，永久受用**——所有小镇变体（童年/少年/老年）、所有室内场景，都靠同一套素材包拼。

## 四、生成要求（重写版）

### 4.1 通用风格锚（不变）

```
扁平手绘插画，暖色调，柔和平涂上色，没有描边，绘本质感，克制留白，中国乡村题材,
```

### 4.2 地砖生成规范

**地砖是最难用 AI 生成的**，因为要求"无缝拼接"。两种策略：

#### 策略 A：AI 生成 + 手动修边缘（推荐）

1. AI 生成一块草地（48×48 或更大）
2. 在 Aseprite/PS 里检查四边能否无缝拼接
3. 手动修边缘让接缝消失
4. 导出为可平铺的 PNG

**提示词模板（草地地砖）：**
```
扁平手绘插画，暖色调，柔和平涂上色，没有描边，
一块正方形的草地纹理，绿色的草地，点缀几朵小野花，
俯视视角，可无缝平铺的纹理图案，48x48像素概念，
纯图案无其他元素，正方形构图
```

**提示词模板（土路地砖）：**
```
扁平手绘插画，暖色调，柔和平涂上色，没有描边,
一块正方形的泥土路纹理，黄褐色的压实泥土，有些小石子,
俯视视角，可无缝平铺的纹理图案，纯图案无其他元素，正方形构图
```

#### 策略 B：AI 生成一张大草坪，你切片

1. AI 生成一张 512×512 的纯草坪
2. 在 PS 里切成 48×48 的小块
3. 挑选能拼接的几块

**这种更快，但拼接质量参差。**

### 4.3 物件生成规范

物件（房子/树/小卖部）相对好生成，因为不需要拼接。

**通用要求：**
- 透明背景 PNG（抠图后）
- 透视：俯视斜 45°（2.5D isometric）
- 底部有"接地阴影"（让它看起来站在地上）

**提示词模板（老槐树）：**
```
扁平手绘插画，暖色调，柔和平涂上色，没有描边，绘本质感，中国乡村题材,
俯视斜45度等距透视，一棵巨大的老槐树，枝叶茂盛形成巨大树冠,
树下有一个旧秋千，树干粗壮盘错,
透明背景，底部有柔和的接地阴影，单独物件，正方形构图
```

**提示词模板（主角家外观）：**
```
扁平手绘插画，暖色调，柔和平涂上色，没有描边，绘本质感，中国乡村题材,
俯视斜45度等距透视，一栋中国乡村的普通民房，红砖墙、灰瓦屋顶,
有木门和窗户，旁边有个小院子,
透明背景，底部有接地阴影，单独物件，竖长构图
```

**提示词模板（小卖部外观）：**
```
扁平手绘插画，暖色调，柔和平涂上色，没有描边，绘本质感，中国乡村题材,
俯视斜45度等距透视，一间中国乡村的老式小卖部，木板门、褪色的招牌,
门口摆着几个纸箱，墙上贴着旧广告,
透明背景，底部有接地阴影，单独物件，竖长构图
```

### 4.4 整套素材包的风格统一技巧

**关键：地砖和物件必须视觉风格完全一致。**

技巧：
1. **用同一套风格锚提示词**
2. **生成完一批后，挑一张最满意的作为"参考图"**，后续生成都用这张做垫图
3. **色调统一**：所有地砖和物件都调到同一暖色调（可在 PS 里统一调色）

## 五、在 Godot 里拼装地图的流程

### 5.1 总流程

```
1. AI 生成素材包（地砖+物件）
   ↓
2. PS/Aseprite 处理（抠图、修边缘、切片）
   ↓
3. 导入 Godot，配置 TileSet 资源
   ↓
4. 新建 TileMap 节点，开始画地图
   ↓
5. 摆放物件（树/房子/小卖部）
   ↓
6. 设置碰撞层（哪些可走、哪些是障碍）
   ↓
7. 放置 NPC 生成点、事件触发点
```

### 5.2 Godot 4 的 TileMap 工作流要点

- 用 **`TileMapLayer`** 节点（Godot 4.3+，比旧 TileMap 更清晰）
- 至少分 **3 层**：
  - 地面层（地砖：草地、土路）
  - 物件层（树、房子、小卖部）
  - 碰撞层（不可见的障碍区域）
- 在 TileSet 编辑器里给每种地砖设置：
  - **碰撞形状**（矩形或多边形，标记障碍）
  - 是否可走

### 5.3 拼装示例：小镇主地图

```
第一步：铺地面层
  全图刷草地 → 在道路位置刷土路 → 河流位置刷水面

第二步：摆物件层
  中心放老槐树 → 旁边放小卖部 → 角落放几栋民房 → 路边放几棵树

第三步：设置碰撞
  房子、树、水 = 障碍（不可走）
  草地、土路 = 可走

第四步：放功能点
  家门口 = 场景传送点（进家）
  小刚家位置 = NPC 生成点
  老槐树下 = 事件触发区
```

**这样拼出来的地图，角色才能真正走在路上、绕开房子、走进小卖部。**

## 六、室内场景怎么处理

### 6.1 室内同样用 TileMap 拼

室内场景（家客厅、教室、小卖部内部）**也用 TileMap 拼**，不要用整张图：

| 室内 | 地砖 | 物件 |
|------|------|------|
| 家客厅 | 木地板地砖 | 沙发、方桌、电视、窗户 |
| 教室 | 石板地砖 | 课桌椅、黑板、国旗、窗户 |
| 小卖部 | 旧地砖 | 货架、柜台、竹椅 |

### 6.2 室内物件单独生成

每个家具作为独立物件生成（透明背景 PNG），在引擎里摆放。

**提示词模板（旧沙发）：**
```
扁平手绘插画，暖色调，柔和平涂上色，没有描边，绘本质感,
俯视斜45度等距透视，一张旧布沙发，暗红色，有些磨损,
透明背景，底部有接地阴影，单独物件
```

## 七、CG 怎么处理（CG 仍是单张整图）

**注意区分：场景地图 vs CG**

| 类型 | 做法 | 原因 |
|------|------|------|
| 场景地图（玩家走动） | **TileMap 拼装** | 角色要走在上面 |
| CG（剧情过场） | **整张 AI 图** | 只是展示，不交互 |

CG 不需要角色走动，只是剧情过场展示，**所以 CG 仍然用 16 号文档的方法生成整张图**，没问题。比如：
- 序章混沌
- 命运之骰
- 小刚告别
- 高考考场
- 结局插画

这些都不用 TileMap。

## 十一、风险与应对

| 风险 | 应对 |
|------|------|
| AI 地砖无法无缝拼接 | PS 手动修边缘，或用切片法 |
| 素材包风格不统一 | 固定风格锚 + 参考图垫图 |
| 拼装后地图看起来空 | 多生成装饰物件（灌木/石头/野花） |
| TileMap 学习成本 | Godot 官方教程 + 参考星露谷类教程 |
| 工作量比整张大 | 但一次拼好永久复用，长期省事 |

## 十二、本节小结

**一句话记住核心：**

> **场景地图 = AI 生成素材包（地砖+物件）+ Godot TileMap 拼装。**
>
> **不是 AI 生成整张图当背景。**

这样角色才能"走"在场景里，而不是"飘"在画上。

**第一步行动：生成第 1 批核心素材包（草地地砖 + 老槐树 + 主角家 + 小卖部），然后在 Godot 里试拼一小块地图，验证工作流可行。**
