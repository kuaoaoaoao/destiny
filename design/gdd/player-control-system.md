# 玩家控制系统

> **Status**: In Design
> **Author**: Claude + User
> **Last Updated**: 2026-06-15
> **Implements Pillar**: Pillar 3（见证者，非英雄）

## Overview

**玩家控制系统**是游戏的基础层，负责将玩家的输入转化为角色在小镇中的移动和交互。它是 30 秒循环（走动 → 遇 NPC → 触发事件）的第一步——没有它，游戏无法运转。

**技术层面**：处理键盘/WASD/手柄输入和触控/点击输入，驱动 `CharacterBody2D` 在 TileMap 上四方向行走，管理角色状态（空闲/行走/交互/等待），并通过 `Area2D` 检测可交互物体。

**玩家体验层面**：玩家操控一个普通人在小镇中散步——移动有真实的重量感，不是漂浮的精灵，而是一个有脚步声、有姿态变化的真实角色。四方向行走配合不同年龄段的体态差异（童年蹦跳、少年正常、老年拖步），让「操控一个人过人生」的感觉从第一步就建立起来。

**核心设计原则**：操控应该直觉到「不需要教程」——玩家看到小镇，自然知道怎么走过去。

## Player Fantasy

**「我就是这个人。」**

玩家操控角色在小镇中行走时，应该感到自己就是这个人——不是在操控一个游戏单位，而是在「过」一种人生。脚步声踩在石板路上，风吹过老槐树的叶子，远处传来小卖部的广播声。移动不是到达目的地的手段，而是**在场**的证明。

**情感锚点**：
- **童年**：在院子里蹦跳，跑向伙伴——无忧无虑的轻快
- **少年**：走向学校，步伐急促——有期待也有紧张
- **青年**：从车站走向城市——脚步沉重但坚定
- **老年**：在老槐树下踱步——缓慢、回望、平静

**支柱服务**：直接服务 Pillar 3（见证者，非英雄）——你不是在操控一个英雄，你是在「成为」一个普通人。也服务 Pillar 4（小镇是情感锚点）——移动让你感受小镇的每一寸空间。

## Detailed Design

### Core Rules

**1. 输入处理**
- **键盘/手柄输入**：WASD/方向键控制四方向移动，空格/回车/手柄 A 键触发交互
- **触控/点击输入**：点击地面自动寻路，点击可交互物体触发交互
- **双输入共存**：两种输入方式同时生效，不互相排斥。检测到键盘输入时隐藏虚拟摇杆，检测到触控时显示

**2. 移动规则**
- 四方向行走（上/下/左/右），不支持斜向移动
- 移动有加速和减速过程（非瞬间达到最高速）
- 碰撞检测：角色与 TileMap 碰撞层、其他 CharacterBody2D 碰撞
- 角色不能穿过障碍物和 NPC

**3. 年龄段移动参数（独立参数集）**

| 年龄段 | 移动速度 | 加速度 | 动画风格 | 碰撞体大小 |
|--------|---------|--------|---------|-----------|
| 童年（7-12） | 慢（80%） | 高（活泼） | 蹦跳、偶尔跑 | 小 |
| 少年（12-18） | 正常（100%） | 正常 | 正常行走，偶尔低头 | 中 |
| 青年（18-30） | 快（110%） | 高 | 步伐急促 | 标准 |
| 中年（30-50） | 正常（95%） | 低 | 微弯、沉稳 | 标准偏宽 |
| 老年（50-80） | 慢（70%） | 低 | 拖步、偶尔停顿 | 标准 |

**4. 交互规则**
- 角色进入可交互物体的 `Area2D` 范围时，显示交互提示（UI 图标）
- 同一时间只能与一个物体交互（最近的优先）
- 交互过程中角色停止移动（锁定状态）
- 交互完成或取消后恢复正常移动

### States and Transitions

| 状态 | 描述 | 可转入 |
|------|------|--------|
| **IDLE** | 站立不动 | WALK, INTERACT |
| **WALK** | 四方向行走 | IDLE, INTERACT |
| **INTERACT** | 与物体/NPC 交互中 | IDLE |
| **WAIT** | 等待（剧情/过场） | IDLE |
| **PATHFIND** | 点击移动自动寻路中 | IDLE, INTERACT |

**状态转换规则**：
- IDLE → WALK：检测到移动输入
- WALK → IDLE：释放移动输入且速度归零
- 任意 → INTERACT：按下交互键且范围内有可交互物体
- INTERACT → IDLE：交互完成
- 任意 → WAIT：剧情系统锁定控制
- WAIT → IDLE：剧情解锁
- IDLE/WALK → PATHFIND：点击地面（触控模式）
- PATHFIND → IDLE：到达目的地或点击取消

### Interactions with Other Systems

| 系统 | 数据流向 | 接口 |
|------|---------|------|
| **场景管理系统** ← | 玩家位置 → 场景触发 | 玩家进入 `Area2D` 触发场景切换 |
| **NPC 日程系统** ← | 玩家位置 → NPC 避让 | NPC 根据玩家位置调整路径 |
| **事件引擎** ← | 交互事件 → 事件触发 | 交互时传递物体 ID 和事件类型 |
| **HUD 系统** ← | 交互提示 → HUD 显示 | 进入交互范围时发送信号 |
| **小镇生活系统** ← | 玩家状态 → 生活系统 | 玩家位置和状态驱动生活循环 |

## Formulas

移动速度公式：
`current_speed = base_speed × age_modifier × state_modifier`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| base_speed | S | float | 100–200 | 基础移动速度（像素/秒） |
| age_modifier | A | float | 0.7–1.1 | 年龄段修正系数 |
| state_modifier | M | float | 0.0–1.0 | 状态修正（交互时为 0） |

**输出范围**：70–220 像素/秒
**示例**：少年行走 = 150 × 1.0 × 1.0 = 150 像素/秒

加速度公式：
`current_acceleration = base_acceleration × age_modifier`

## Edge Cases

- **如果角色卡在障碍物中**：回退到上一帧位置，重置速度为 0
- **如果两个交互物体重叠**：选择距离角色中心最近的物体
- **如果在交互过程中场景切换**：取消交互，重置为 IDLE 状态
- **如果点击移动目标不可达**：寻路失败，角色停在最近可达点

## Dependencies

无上游依赖。被以下系统依赖：
- **小镇生活系统**：依赖玩家位置和状态驱动生活循环
- **HUD 系统**：依赖交互提示信号显示 UI

## Tuning Knobs

| 旋钮 | 默认值 | 范围 | 说明 |
|------|--------|------|------|
| base_speed | 150 | 100–200 | 基础移动速度 |
| acceleration_time | 0.2s | 0.1–0.5 | 加速到最高速的时间 |
| deceleration_time | 0.15s | 0.05–0.3 | 减速到停止的时间 |
| interaction_range | 48px | 32–96 | 交互检测范围 |
| pathfinding_arrival_distance | 8px | 4–16 | 寻路到达判定距离 |

## Visual/Audio Requirements

- 四方向行走动画（每个年龄段独立 sprite）
- 脚步声（根据地面材质变化：石板路/泥土/木地板）
- 交互提示图标（靠近物体时显示）
- 年龄段体态差异通过动画体现（非碰撞体变形）

## UI Requirements

- 交互提示 HUD：靠近可交互物体时显示按键提示或点击区域
- 虚拟摇杆（移动端）：检测到触控输入时显示

## Acceptance Criteria

- GIVEN 玩家按下 WASD，WHEN 角色在空旷区域，THEN 角色以四方向移动，速度符合年龄段参数
- GIVEN 玩家靠近可交互物体，WHEN 进入交互范围，THEN 显示交互提示图标
- GIVEN 玩家按下交互键，WHEN 范围内有可交互物体，THEN 角色停止移动并触发交互
- GIVEN 玩家点击地面（触控模式），WHEN 目标可达，THEN 角色自动寻路到目标位置
- GIVEN 童年年龄段，WHEN 角色移动，THEN 动画为蹦跳风格，速度为 80%
- GIVEN 角色碰撞障碍物，WHEN 移动方向有障碍，THEN 角色停止，不穿过障碍物

## Open Questions

- 移动端虚拟摇杆的具体样式和布局需要 UX 设计
- 不同地面材质的音效列表需要音效设计确认
- 点击移动的寻路算法选择（A* vs NavigationServer）需要技术决策
