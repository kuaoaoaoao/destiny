# 小游戏框架

> **Status**: Designed
> **Author**: Claude + User
> **Last Updated**: 2026-06-15
> **Implements Pillar**: Pillar 1（真实大于戏剧）— 小游戏融入剧情

## Overview

**小游戏框架**是游戏的功能层，为高考答题等小游戏提供统一的框架。小游戏融入剧情，不是独立的休闲玩法。

**技术层面**：独立 mini-scene，结果回传数值系统。支持多种小游戏类型（答题、节奏、反应）。

**玩家体验层面**：玩家在人生关键节点体验小游戏——高考答题的紧张感、面试的对话选择。小游戏结果直接影响人生走向。

**核心设计原则**：小游戏应该「融入剧情」——不是独立的休闲玩法，而是人生体验的一部分。

## Player Fantasy

**「这就是人生的考验。」**

玩家玩小游戏时，应该感到这是人生的「关键时刻」——高考不只是答题，是人生分水岭；面试不只是选择，是职业起点。小游戏结果有重量。

**支柱服务**：直接服务 Pillar 1（真实大于戏剧）— 小游戏融入剧情，不独立存在。

## Detailed Design

### Core Rules

**1. 小游戏类型**

| 类型 | 说明 | 示例 |
|------|------|------|
| **答题** | 限时选择题 | 高考答题 |
| **节奏** | 节奏点击 | 偷偷玩游戏 |
| **反应** | 反应速度 | 抓知了/鱼 |
| **对话** | 选择话题 | 面试、相亲 |

**2. 小游戏流程**
- 触发条件满足 → 进入小游戏场景
- 玩家执行小游戏操作
- 计算结果 → 回传数值系统
- 返回主场景

**3. 结果回传**
- 小游戏结果直接修改六大数值
- 结果有随机浮动（±15%）
- 结果影响后续事件

### Interactions with Other Systems

| 系统 | 数据流向 | 接口 |
|------|---------|------|
| **场景管理系统** ← | 小游戏场景 → 场景切换 | 场景切换接口 |
| **命运系统** ← | 小游戏结果 → 数值修改 | 调用接口：`modify_stats(effects)` |
| **事件引擎** ← | 小游戏触发 → 事件执行 | 信号：`minigame_triggered` |

## Formulas

小游戏结果公式：
`final_score = raw_score × difficulty_modifier × random_factor`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| raw_score | R | float | 0–100 | 原始分数 |
| difficulty_modifier | D | float | 0.5–1.5 | 难度修正 |
| random_factor | F | float | 0.85–1.15 | 随机浮动 |

## Edge Cases

- **如果小游戏过程中游戏崩溃**：返回主场景，不应用结果
- **如果小游戏结果无效**：使用默认结果
- **如果小游戏触发条件在小游戏进行中变化**：以开始时的条件为准

## Dependencies

依赖：
- **场景管理系统**：加载小游戏场景
- **命运系统**：回传数值结果

被以下系统依赖：
- **人生节点系统**：触发小游戏

## Tuning Knobs

| 旋钮 | 默认值 | 范围 | 说明 |
|------|--------|------|------|
| minigame_difficulty | 1.0 | 0.5–1.5 | 小游戏难度系数 |
| random_factor_range | 15% | 10–20% | 结果随机浮动范围 |

## Visual/Audio Requirements

- 小游戏场景的独立视觉风格
- 小游戏的操作反馈（音效/动画）
- 小游戏结果的展示

## UI Requirements

- 小游戏操作界面
- 小游戏结果展示

## Acceptance Criteria

- GIVEN 高考触发，WHEN 进入小游戏，THEN 显示答题界面
- GIVEN 小游戏完成，WHEN 计算结果，THEN 数值正确更新
- GIVEN 小游戏结果，WHEN 应用随机浮动，THEN 结果在合理范围内
