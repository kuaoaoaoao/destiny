# 时间系统

> **Status**: Designed
> **Author**: Claude + User
> **Last Updated**: 2026-06-15
> **Implements Pillar**: Pillar 4（小镇是情感锚点）— 时间驱动小镇变化

## Overview

**时间系统**是游戏的基础层，负责管理两层时间：日内时间（实时流逝）和人生年龄（节点推进）。它是 5 个系统的依赖基础——NPC 日程、事件引擎、人生节点、HUD、命运系统都依赖它获取时间状态。

**技术层面**：Autoload 单例 `TimeManager`，管理日内时间（早晨/白天/傍晚/夜晚）和人生年龄（0-80 岁）。提供时间查询接口和时间推进信号。

**玩家体验层面**：玩家感受到时间的流逝——天色变化、NPC 位置变化、季节更替。时间不是抽象的数字，而是小镇生活的节奏。

**核心设计原则**：时间应该「被感受到，不被注意到」——它是背景音乐，不是前景噪音。

## Player Fantasy

**「日子一天天过去，人生一年年流逝。」**

玩家在小镇中漫步时，应该感到时间在流动——早晨的阳光、傍晚的炊烟、夜晚的虫鸣。时间推动着一切：伙伴在长大、父母在变老、小镇在变化。每一次回家睡觉，都是一次时间的跳跃；每一个关键日，都是一次人生的分水岭。

**支柱服务**：直接服务 Pillar 4（小镇是情感锚点）——时间让小镇「活」起来，不同时间有不同的面貌。

## Detailed Design

### Core Rules

**1. 双层时间结构**

| 层级 | 单位 | 推进方式 | 用途 |
|------|------|---------|------|
| **日内时间** | 一天 | 实时流逝（1 天 ≈ 3-5 分钟） | 小镇探索、NPC 遇见、事件触发 |
| **人生年龄** | 一岁 | 关键事件后推进 | 阶段切换、数值演变、命运走向 |

**2. 日内时间规则**
- 一天分为 4 个时段：早晨（6:00-10:00）、白天（10:00-17:00）、傍晚（17:00-20:00）、夜晚（20:00-6:00）
- 时间实时流逝，1 个游戏日 = 3-5 分钟现实时间
- 玩家回家睡觉 → 跳到次日早晨
- 时间流逝速度可通过 Tuning Knob 调整

**3. 人生年龄规则**
- 年龄从 0 岁开始，到 80 岁结束
- 大部分日子是「日常生活」，快速跳过（蒙太奇）
- 到达关键日（7/12/15/18/22/28/35/45/60 岁）时，进入「剧情日」
- 剧情日：玩家自由探索 + 触发关键事件 + 做重大选择

**4. 节奏控制**

| 年龄段 | 游戏节奏 | 每段游戏时间 |
|--------|---------|------------|
| 童年（0-6） | 纯观看，快速蒙太奇 | ~2 分钟 |
| 童年（7-12） | 每个关键年玩 1-2 天 | ~10 分钟 |
| 少年（12-18） | 每 2-3 年玩 1-2 天 | ~15 分钟 |
| 青年（18-30） | 每年关键节点玩 1-2 天 | ~15 分钟 |
| 中年（30-50） | 重大事件触发才玩 | ~10 分钟 |
| 老年（50-80） | 慢节奏，回望感 | ~8 分钟 |

**MVP 只实现**：童年关键日（7、12 岁）+ 少年关键日（15、18 岁高考）。单次人生 30-50 分钟。

### States and Transitions

| 状态 | 描述 | 可转入 |
|------|------|--------|
| **MONTAGE** | 蒙太奇（快速跳过） | KEY_DAY |
| **KEY_DAY** | 剧情日（自由探索） | MONTAGE, END |
| **PAUSED** | 时间暂停（菜单/对话） | KEY_DAY |
| **END** | 人生结束 | — |

**状态转换规则**：
- MONTAGE → KEY_DAY：到达关键日年龄
- KEY_DAY → MONTAGE：关键日结束（回家睡觉）
- 任意 → PAUSED：打开菜单或进入对话
- PAUSED → 前一状态：关闭菜单或对话结束
- KEY_DAY → END：到达 80 岁或触发结局事件

### Interactions with Other Systems

| 系统 | 数据流向 | 接口 |
|------|---------|------|
| **事件引擎** ← | 当前时间 → 事件触发条件 | 查询当前时段和年龄 |
| **NPC 日程系统** ← | 当前时段 → NPC 位置 | 信号：`time_period_changed` |
| **人生节点系统** ← | 当前年龄 → 关键日判断 | 信号：`age_reached(age)` |
| **HUD 系统** ← | 当前时间 → 时间显示 | 查询接口：`get_current_time()` |
| **命运系统** ← | 当前年龄 → 数值演变 | 查询接口：`get_current_age()` |

## Formulas

日内时间推进公式：
`game_time += delta × time_scale`

| 变量 | 符号 | 类型 | 范围 | 描述 |
|------|------|------|------|------|
| delta | δ | float | 0.016–0.033 | 帧间隔时间（秒） |
| time_scale | S | float | 1.0–10.0 | 时间缩放系数 |

**输出范围**：0–1440 游戏分钟/天
**示例**：delta=0.016, time_scale=5.0 → 每帧推进 0.08 游戏分钟

## Edge Cases

- **如果玩家在关键日不回家睡觉**：时间自动推进到夜晚 23:59，然后强制跳到次日
- **如果两个关键事件同一天触发**：按优先级顺序执行（人生节点 > 普通事件）
- **如果玩家在对话中时间流逝**：暂停日内时间，对话结束后恢复
- **如果蒙太奇期间有未完成事件**：标记为「错过」，不触发

## Dependencies

无上游依赖。被以下系统依赖：
- **事件引擎**：依赖时间条件检查
- **NPC 日程系统**：依赖时段切换信号
- **人生节点系统**：依赖年龄到达信号
- **HUD 系统**：依赖时间查询接口
- **命运系统**：依赖年龄查询接口

## Tuning Knobs

| 旋钮 | 默认值 | 范围 | 说明 |
|------|--------|------|------|
| time_scale | 5.0 | 1.0–10.0 | 日内时间缩放系数 |
| day_duration_minutes | 4.0 | 3.0–5.0 | 一个游戏日的现实时间（分钟） |
| montage_speed | 100.0 | 50.0–200.0 | 蒙太奇时间推进速度倍率 |
| key_day_ages | [7,12,15,18] | — | MVP 关键日年龄列表 |

## Visual/Audio Requirements

- 天色随日内时间变化（早晨暖黄 → 白天明亮 → 傍晚橙红 → 夜晚深蓝）
- 环境音随时间变化（鸟叫/蝉鸣/蟋蟀/寂静）
- 年龄推进时的过场动画（蒙太奇效果）

## UI Requirements

- HUD 显示当前时段图标（太阳/月亮）
- 关键日到达时的提示 UI

## Acceptance Criteria

- GIVEN 游戏运行，WHEN 1 个游戏日过去，THEN 时间从早晨推进到夜晚
- GIVEN 玩家回家睡觉，WHEN 按下睡觉按钮，THEN 时间跳到次日早晨
- GIVEN 到达关键日年龄（如 7 岁），WHEN 蒙太奇结束，THEN 进入剧情日
- GIVEN 玩家打开菜单，WHEN 菜单打开中，THEN 日内时间暂停
- GIVEN 蒙太奇状态，WHEN 时间推进，THEN 速度为正常速度的 100 倍
