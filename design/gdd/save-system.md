# 存档系统

> **Status**: Designed
> **Author**: Claude + User
> **Last Updated**: 2026-06-15
> **Implements Pillar**: Pillar 5（多周目见全貌）— 存档支持多周目体验

## Overview

**存档系统**是游戏的核心层，负责管理游戏进度的保存和加载。多周目体验需要可靠的存档支持。

**技术层面**：使用 JSON 序列化游戏状态，支持自动存档和手动存档。存档包含：六大数值、NPC 好感度、已触发事件、当前年龄、场景状态。

**玩家体验层面**：玩家可以随时保存进度，下次继续。多周目体验需要多个存档槽位。

**核心设计原则**：存档应该「可靠且透明」——玩家知道存档了什么，不会丢失进度。

## Player Fantasy

**「我的每一段人生都被记录。」**

玩家存档时，应该感到自己的人生被完整记录——不只是数值，还有与伙伴的关系、做过的选择、经历的事件。每次加载存档，都是「继续我的人生」。

**支柱服务**：直接服务 Pillar 5（多周目见全貌）— 存档支持多周目体验。

## Detailed Design

### Core Rules

**1. 存档内容**

| 数据 | 说明 |
|------|------|
| 玩家状态 | 六大数值、当前年龄、当前位置 |
| NPC 状态 | 好感度、人生线状态 |
| 事件状态 | 已触发事件列表 |
| 场景状态 | 各场景的 NPC 位置和物体状态 |
| 时间状态 | 当前日内时间和人生年龄 |

**2. 存档方式**
- **自动存档**：每天睡觉时自动保存
- **手动存档**：玩家通过菜单手动保存
- **存档槽位**：3 个手动存档槽位 + 1 个自动存档槽位

**3. 存档格式**
- JSON 格式，可读可编辑
- 存档文件存储在用户目录

### Interactions with Other Systems

| 系统 | 数据流向 | 接口 |
|------|---------|------|
| **命运系统** ← | 数值状态 → 存档 | 序列化接口 |
| **NPC 平行人生系统** ← | 人生线状态 → 存档 | 序列化接口 |
| **事件引擎** ← | 事件状态 → 存档 | 序列化接口 |
| **场景管理系统** ← | 场景状态 → 存档 | 序列化接口 |

## Formulas

存档大小公式：
`save_size = base_size + (event_count × event_size) + (npc_count × npc_size)`

## Edge Cases

- **如果存档文件损坏**：显示错误提示，提供备份恢复
- **如果存档时正在场景切换中**：等待切换完成后再存档
- **如果存档版本不兼容**：显示版本不兼容提示

## Dependencies

依赖：
- **命运系统**：序列化数值状态
- **NPC 平行人生系统**：序列化人生线状态
- **事件引擎**：序列化事件状态

被以下系统依赖：
- 无直接下游依赖

## Tuning Knobs

| 旋钮 | 默认值 | 范围 | 说明 |
|------|--------|------|------|
| auto_save_enabled | true | — | 是否启用自动存档 |
| save_slot_count | 3 | 1–5 | 手动存档槽位数 |

## Visual/Audio Requirements

- 存档/读档的 loading 动画
- 存档成功的提示音效

## UI Requirements

- 存档/读档菜单
- 存档槽位选择
- 存档预览（年龄、数值摘要）

## Acceptance Criteria

- GIVEN 玩家睡觉，WHEN 自动存档触发，THEN 游戏状态正确保存
- GIVEN 玩家手动存档，WHEN 选择槽位，THEN 游戏状态保存到指定槽位
- GIVEN 玩家读档，WHEN 选择存档，THEN 游戏状态正确恢复
- GIVEN 存档文件损坏，WHEN 尝试读档，THEN 显示错误提示
