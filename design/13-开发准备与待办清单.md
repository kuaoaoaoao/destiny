## 三、技术选型

### 3.1 游戏引擎：Godot 4.3+（已确定）

| 引擎 | 评估 |
|------|------|
| **Godot 4.3+** ✅ | 开源免费、2D/2.5D 优秀、轻量、TileMapLayer 稳定、Dialogic 插件成熟 |
| Unity | 生态好但包体大、2D 支持一般 |
| Ren'Py | 只适合纯视觉小说，不适合 2.5D 操控 |

**为什么 Godot 4 而不是 3：**
- TileMapLayer 节点（4.3+）比旧 TileMap 更适合多层小镇
- GDScript 2.0 类型推断好，适合中大型项目
- UI 系统（Control 节点）成熟

### 3.2 关键插件/工具

| 工具 | 用途 | 状态 |
|------|------|------|
| **Dialogic** | 对话系统（分支/变量/立绘） | 推荐使用 |
| **Godot SQLite** | 存档/复杂查询（可选） | 备选 |
| **Aseprite** | 像素美术制作 | 美术工具 |
| **Tiled** | 地图设计辅助（可选） | 备选 |
| **LDtk** | 关卡设计（可选） | 备选 |

### 3.3 技术风险评估

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| **命运全景图回溯演算** | 高 | 核心卖点 | M2 早期预研，最坏降级为静态展示 |
| 2.5D 小镇性能 | 中 | 卡顿 | TileMap 优化、限制 NPC 数量 |
| 存档系统复杂度 | 中 | 数据丢失 | 早期定义清晰数据结构 |
| 对话系统学习成本 | 低 | 延期 | 用 Dialogic 而非自研 |
| 跨平台兼容 | 低 | 延期 | 优先 PC |

## 四、垂直切片原型（v0.3 新定义）

### 4.1 原型目标（重定义）

**v0.3 转向后，原型不再是"纯文本流程"，而是"星露谷式小镇生活的垂直切片"。**

原型需要验证的核心问题：

| 问题 | 验证方式 |
|------|---------|
| 在小镇走动遇伙伴，有没有"在场感"？ | 玩 10 分钟观察反应 |
| 2.5D 操控是否顺畅、不晕？ | 观察 |
| 高考小游戏的紧张感能否传达？ | 体验后访谈 |
| 小刚告别场景能否打动人？ | 找 5 人测试情绪反应 |
| 数值变化玩家能否感知"选择有重量"？ | 体验后访谈 |
| 玩完想不想再玩一次看不同命运？ | 关键留存指标 |

### 4.2 垂直切片范围（MVP）

| 功能 | MVP 是否包含 | 说明 |
|------|------------|------|
| 命运之骰（出生） | ✅ | 但只支持 1 种出身（农村普通×男） |
| **小镇地图（1张主图）** | ✅ | 家+学校+老槐树+小卖部+小刚家+小芳家 |
| **角色操控（2.5D移动）** | ✅ | WASD 四方向行走 |
| **NPC（小刚+小芳+父母+老师）** | ✅ | 日程+对话 |
| 童年（7、12岁关键日） | ✅ | 简化版 |
| 少年（15、18岁高考） | ✅ | 含高考小游戏 |
| **高考小游戏** | ✅ | 限时答题 |
| 事件 | ✅ | 30-40 个核心事件 |
| 数值系统（6大数值） | ✅ | 基础版 |
| 命运之书（基础版） | ✅ | 关键事件+数值 |
| 中年/老年 | ❌ | 留 M3/M4 |
| 城市地图 | ❌ | 留 M2 |
| 命运全景图 | ❌ | 留 M3（最高风险，单独预研） |
| 全知模式 | ❌ | 留 M4 |
| 多结局 | ❌ | MVP 到 18 岁给"未完待续" |
| NPC 多版本随机 | ❌ | MVP 写死，留 M3 |

**MVP 单次时长：** 20-30 分钟（0-18 岁一条线）

### 4.3 垂直切片开发计划

| 阶段 | 时间 | 内容 | 交付 |

| **M1 垂直切片** | 第 3-8 周 | 小镇+NPC+事件+高考小游戏+0-18岁 | **可玩 MVP** |

## 五、数据结构规范（v0.3 新增，最高优先级）

> ⭐ **这是整个项目的地基。222+ 事件、10 个 NPC 人生线、6 种出身、10 种结局，全部用 JSON 定义，绝不在代码里写死。数据结构定不好，后面全乱。**

### 5.1 出身数据（backgrounds.json）

```json
{
  "backgrounds": {
    "rural_poor": {
      "name": "农村贫困家庭",
      "weight": 20,
      "initial_stats": {
        "money": 10, "social": 5, "education": 5,
        "mental": 15, "health": 20, "happiness": 15
      },
      "home_scene": "home_poor",
      "parents": {
        "father": { "status": "migrant_worker", "present": false },
        "mother": { "status": "farmer", "present": true }
      },
      "core_conflict": "我连活着都费力，谈什么梦想？"
    }
  }
}
```

### 5.2 事件数据（events/childhood.json 等）

```json
{
  "events": {
    "C026": {
      "name": "被同学欺负",
      "stage": "childhood",
      "age_range": [7, 12],
      "trigger": {
        "type": "location",
        "location": "school_playground_corner",
        "conditions": [
          { "stat": "social", "op": "<", "value": 40 }
        ]
      },
      "narrative": "narrative_C026",
      "choices": [
        {
          "text": "忍耐",
          "effects": { "mental": -15, "social": -10 },
          "flags": ["bullied_silent"]
        },
        {
          "text": "反抗",
          "effects": { "mental": -5, "social": 5, "health": -10 },
          "conditions": [{ "stat": "health", "op": ">", "value": 30 }],
          "flags": ["bullied_fight"]
        },
        {
          "text": "告诉老师",
          "effects": { "social": -5, "education": 5 }
        }
      ]
    }
  }
}
```

### 5.3 NPC 人生线数据（npcs/xiaogang.json）

详见 15 号文档第十一节。每个伙伴一个 JSON 文件，含多个版本时间线。

### 5.4 结局数据（endings.json）

```json
{
  "endings": {
    "ordinary_life": {
      "name": "平凡一生",
      "conditions": {
        "money": [30, 60], "mental": [40, 60], "health": [40, 60],
        "social": [30, 60], "has_family": true, "no_major_trauma": true
      },
      "evaluation": "平凡但完整",
      "happiness_range": [55, 65],
      "ending_cg": "ending_ordinary"
    }
  }
}
```

### 5.5 字段约定（全局）

| 字段类型 | 约定 |
|---------|------|
| `stat` | money/mental/health/social/education/happiness 之一 |
| `op` | <, >, <=, >=, ==, != |
| `effects` | 数值变化对象，如 `{"mental": -15}` |
| `flags` | 事件标记，用于条件判断和全景图 |
| `conditions` | 条件数组，全部满足才触发 |

### 5.6 数据驱动开发原则

1. **策划改文案/数值只改 JSON，不改代码**
2. **事件/NPC/结局的可组合性要高**（同一事件能被多种出身触发）
3. **写 JSON Schema 校验**，避免格式错误
4. **写自动化测试**，验证时间线一致性（如 NPC 事件不冲突）

## 六、美术策略（v0.3 更新）

### 6.1 美术风格定型：扁平手绘 2.5D + AI 生成

| 维度 | 规格 |
|------|------|
| 风格 | 扁平手绘插画，暖色调，绘本质感 |
| 视角 | 俯视斜 45°（2.5D isometric） |
| **生成方式** | **AI 生成**（即梦/可灵/通义/Midjourney） |
| 动画 | MVP 四方向静帧；完整版 Spine 骨骼动画 |
| 主角 | 无明确五官（代入感），姿态/体形变化 |
| NPC | 有辨识度特征 |

> ⚠️ 原"48px 像素"方案已废弃。详细生成规范见 **16 号文档**。

### 6.2 美术分阶段策略

| 阶段 | 策略 | 说明 |
|------|------|------|
| **MVP** | AI 生成正式素材 | 不是占位，直接生成可用的扁平手绘素材 |
| **定型期** | 验证风格后批量生成 | 先做 3 张定"基础脸/基础场景" |
| **完整版** | AI 生成全部 + 手工拆层/修字 | 场景分层、中文字 PS 手动加 |

### 6.3 AI 素材来源与工具

| 资源 | 工具 | 说明 |
|------|------|------|
| 场景/角色/CG | 即梦/可灵/通义/Midjourney | AI 生成，详见 16 号文档 |
| 字体 | 思源宋体 + 思源黑体 | OFL（免费商用） |
| 音效 | freesound.org / kenney sfx | CC0 |
| BGM | 暂用免费钢琴曲或自录 | CC0 |
| 拆层/修字 | Photoshop / Aseprite | AI 出图后手工处理 |

> **重要：AI 生成素材要保留提示词和 seed 记录，便于复用风格。详见 16 号文档第七节。**

### 6.4 完整版美术资源需求

| 资源类型 | 数量 | 说明 |
|---------|------|------|
| 场景（主图+室内） | 10-15 张 | 乡村/小镇/城市 × 关键地点 |
| 主角立绘 | 5 张 | 童年/少年/青年/中年/老年 |
| 主角行走图 | 5 套 | 同上（四方向或 Spine） |
| NPC 立绘 | 10 个 | 6伙伴+4长辈 |
| NPC 多版本变体 | ~20 张 | 同一 NPC 不同人生状态 |
| CG 插画 | 20-30 张 | 关键剧情大图 |
| 结局插画 | 10 张 | 10种结局 |
| UI 图标 | 60-80 个 | 数值/物品/成就 |
